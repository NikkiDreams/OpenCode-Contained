# Code Review

## When to Use This Skill
- Pull request or diff needs review
- Checking recent code changes for bugs, security issues, or design problems
- Providing constructive feedback on implementation quality

## Workflow
1. Load the diff or changed files
2. Identify the core intent of the changes
3. Focus review on correctness, security, and design — skip stylistic nitpicks
4. Flag real problems with clear explanations of why they matter
5. Suggest concrete fixes, not vague criticisms
6. Acknowledge what's done well

## Rules
- Review what matters: correctness, security, performance, and maintainability
- Provide actionable feedback — every comment should suggest a fix
- Avoid bikeshedding on formatting and naming preferences
- Don't be adversarial — frame feedback as collaboration
- Skip minor issues if they don't affect behavior
- Check for edge cases, error handling, and input validation
